## Installing PlanktoQNT for the first time

Required to install SQLite

Clone the repository on your computer

Create and activate a virtual environment

```
python3 -m venv .venv
source .venv/bin/activate
```

Install dependencies (requirements.txt)

```
pip install --upgrade pip
pip install -r requirements.txt.
```

## Create a new project

Prepare a project folder. You can use 00_template as a reference.

```
Projects/
└── 00_template/
    ├── config.yaml
    ├── 01_notebooks/
    ├── 02_metadata/
    │   ├── IFCB_info.csv
    │   └── taxonomic_info.csv
    └── 03_datasets/
```

Create:
**'IFCB_info.csv'** containing the experimental setup info, and
**'taxonomic_info.csv'** containing the taxonomy info per group based on WoRMS (will automate this process in the future with [TaxonomyMatch](https://github.com/VirginieSonnet/TaxonomyMatch))

In your project, edit the config.yaml file to set the paths to the outputs from ifcb-analysis and PlanktoNET (root directory) as shown below:

```
project_name: "00_template"

paths:
  ifcb_feature_output: "/path/to/ifcb-analysis/Data/YOUR_PROJECT/feature_output"
  planktonet_results: "/path/to/PlanktoNET/results"

settings:
  confidence_threshold: 0.60
```

## Running PlanktoQNT

From the root folder, activate the virtual environment:

```
source .venv/bin/activate
```

Then, ==run the pipeline==:

```
python run_pipeline.py --config Projects/00_template/config.yaml
```

## Description of *run_pipeline.py* steps

### Step 01 — IFCB feature database

This step reads all feature files (`*_fea_v2.csv`) generated by `ifcb-analysis` and compiles them into a single SQLite database. High-dimensional features used for machine learning (e.g., Wedge, Ring, HOG) are removed, and multi-blob particles are corrected by replacing geometric variables with their summed equivalents when multiple blobs are detected. Each particle is assigned a unique identifier (`file_name_w_roi`), and experimental metadata is merged using the sample (`folder_id`). The output is a consolidated particle-level database used for all downstream analyses.

#### features

The following features are extracted on step01 to estimate optical size and biovolume:
 • **Area**: The total number of pixels within the ROI, representing its two-dimensional size.
 • **Biovolume**: An estimation of the three-dimensional volume of the organism, derived from the area and shape assumptions.
 • **BoundingBox_xwidth** and **BoundingBox_ywidth**: The width and height of the smallest rectangle that can enclose the ROI, indicating its spatial dimensions.
 • **EquivDiameter**: The diameter of a circle with the same area as the ROI, providing a size metric.
 • **FeretDiameter**: The longest distance between any two points along the ROI boundary, also known as the maximum caliper diameter.
 • **MajorAxisLength** and **MinorAxisLength**: Lengths of the major and minor axes of the ellipse that has the same normalized second central moments as the ROI, describing its elongation.
 • **Perimeter**: The total length around the boundary of the ROI.
 • **ConvexArea**: The area of the convex hull that encloses the ROI, useful for understanding the object’s solidity.
 • **ConvexPerimeter**: The perimeter of the convex hull around the ROI.
 • **Extent**: The ratio of the ROI area to the area of its bounding box, indicating how much of the bounding box is filled by the ROI.

### Step 02 — PlanktoNET classification database

This step reads the `confidence.tsv` files generated by PlanktoNET for each IFCB sample folder and compiles the classification results into a single SQLite database. For each image, the script extracts the sample name, ROI number, unique particle identifier (`file_name_w_roi`), predicted class, and classification probability. Taxonomic metadata from `taxonomic_info.csv` is then merged with the classification table. The output is a particle-level classification database used for merging with IFCB feature data in the next step.

### Step 03 — Merge features and classification

This is the final RAW integrated dataset

```
features + classification + metadata
```

This step merges the IFCB feature database with the PlanktoNET classification database using the unique particle identifier (`file_name_w_roi`). Each particle is assigned its corresponding predicted class and classification probability while preserving all geometric and biovolume features. The output is a combined particle-level dataset used for filtering, biomass estimation, and ecological analysis.

### Step 04 — Particle-level carbon biomass

Optical biovolume derived from IFCB images → Carbon
This step converts particle biovolume from pixel units to µm³ using a calibration factor and applies published allometric relationships to estimate carbon biomass (pg C cell⁻¹). Carbon conversion formulas are assigned based on taxonomic category (e.g., diatoms, dinoflagellates, ciliates, detritus). The output is a particle-level dataset including biovolume, carbon content (pgC and µgC), and classification information, which serves as the basis for abundance and biomass analyses.

### Step 05 — Sample-level taxonomic abundance and biomass

This step aggregates particle-level data into sample-level summaries for each IFCB run and taxonomic group (e.g., category, genus, or taxon_name). For each group within each sample, the total number of particles and total carbon biomass are calculated and normalized by the analyzed volume to obtain abundance (particles L⁻¹) and carbon biomass (µg C L⁻¹). The grouping variable is configurable, allowing flexible analysis at different taxonomic resolutions. The output provides the core dataset for downstream ecological analysis, including community composition, size structure, and biomass partitioning.

### Step 06 — Technical replicate merging (Aggregation)

This step combines duplicate IFCB runs that represent the same biological sample, defined by shared year, day, treatment, replicate, and taxonomic grouping. Particle counts and carbon biomass are summed across duplicate runs, and the effective analyzed volume is also summed. Abundance and biomass are then recalculated using the combined volume, producing one row per biological replicate and taxonomic group. This step was necessary for the '01_Microcosm_Ishigaki_2023' project because two runs corresponded to the same biological sample (5 + 5 = 10 ml analyzed per sample).

### Step 07 — Ecological metrics

This step calculates replicate-level ecological metrics from the merged technical-replicate summary. For each biological replicate, total abundance, total carbon biomass, richness, Shannon diversity, and Simpson dominance are calculated. The step also computes the relative contribution of each taxonomic group to total abundance and biomass, providing the basis for community composition and biomass partitioning analyses.
Warning: diversity based on PlanktoNET classes is only as reliable as the classification system. Use these metrics as **classification-based ecological indices**, not as perfect species diversity.

### Step 08 — Export datasets

This step exports the final processed datasets from SQLite format to CSV files for analysis, visualization, and publication. The outputs include replicate-level ecological metrics and taxonomic group contributions, providing ready-to-use tables for statistical analysis and figure generation.

### ### Step 09 — Morphometry summary

This step calculates average morphological and biomass properties per taxonomic group (e.g., taxon_name, category, genus, or class_name). Metrics include area, biovolume, equivalent diameter (EquivDiameter), axis lengths, and carbon biomass (pgC and µgC), along with standard deviation and standard error. Output is saved into '03_datasets/07_metrics/'.
